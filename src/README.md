# Hospital Management System

A Java Swing-based Hospital Management System developed as the final project for the Advanced Programming course.

The system provides a graphical interface for managing patients, doctors, wards, appointments, medical services, bills, and hospital income.

---

## 1. Project Overview

The Hospital Management System is designed to simulate the basic administrative and operational processes of a hospital.

The application allows the user to:

* Manage patients
* Manage doctors
* Manage hospital wards
* Create and manage appointments
* Manage medical services
* Manage patient bills and charges
* View hospital income and budget
* Admit and discharge patients
* Assign patients and doctors to wards
* Transfer patients and doctors between wards
* Store and load hospital data using a database

The graphical user interface is implemented using Java Swing.

## 4. Main Components

### Core

The `Hospital.Core` package contains the main business logic and domain classes.

Important classes include:

* `HospitalSystem` — manages the main hospital data and operations.
* `Patient` — represents a hospital patient.
* `Doctor` — represents a hospital doctor.
* `Ward` — represents a hospital ward and its patients and doctors.
* `Appointment` — represents an appointment between a patient and a doctor.
* `MedicalRecord` — stores a patient's medical information.
* `MedicalService` — represents a medical service provided by the hospital.
* `Bill` — manages a patient's charges.
* `Charge` — represents an individual charge.
* `HospitalIncome` — represents income generated by the hospital.
* `WardBonus` — represents income generated when a ward becomes empty of patients.

### GUI

The `Hospital.GUI` package contains the Swing graphical user interface.

The interface is divided into multiple panels for different hospital operations, including:

* Hospital overview
* Patient management
* Doctor management
* Ward management
* Appointment management
* Medical service management
* Hospital billing and income

`CardLayout` is used to switch between the different application screens.

### Database

The database-related classes are responsible for saving and loading application data.

* `DatabaseSaver` saves the current hospital data.
* `DatabaseLoader` loads previously saved hospital data.
* SQLite is used as the database engine.

## 5. Main Features

### Patient Management

The system supports:

* Adding patients
* Editing patient information
* Viewing patient information
* Deleting patients
* Assigning patients to wards
* Transferring patients between wards
* Discharging patients

When a patient is discharged, the patient's ward assignment is removed. If the discharge causes the ward to become empty of patients, the corresponding ward bonus is added to hospital income.

### Doctor Management

The system supports:

* Adding doctors
* Editing doctors
* Viewing doctors
* Deleting doctors
* Assigning doctors to wards
* Transferring doctors between wards
* Managing doctor appointments

Doctors are associated with their assigned wards independently from patients.

### Ward Management

The system supports:

* Adding wards
* Viewing wards
* Editing ward information
* Managing ward capacity
* Viewing patients in a ward
* Viewing doctors in a ward

A ward cannot accept additional patients when its capacity has been reached.

### Appointment Management

Appointments connect patients and doctors and contain:

* Patient
* Doctor
* Date
* Time
* Appointment status

The system checks several appointment conditions, including:

* Doctor availability
* Doctor daily capacity
* Doctor working hours
* Existing appointments
* Ward compatibility between the patient and doctor

### Medical Services and Billing

The system supports:

* Adding medical services
* Creating charges for patients
* Removing charges when appropriate
* Calculating patient bills
* Displaying hospital income

Hospital income can include income generated from medical services and ward bonuses.

## 6. Database

The application uses SQLite for persistent storage.

The database stores the information required to restore the hospital system when the application is started again.

When the application is closed, the current data is saved to the database.

When the application starts, the stored data can be loaded into the hospital system.

## 7. How to Run the Project

### Requirements

Before running the application, make sure the following are installed:

1. Java JDK 17 or later
2. IntelliJ IDEA or another Java IDE
3. SQLite JDBC driver

### Running in IntelliJ IDEA

1. Open the project in IntelliJ IDEA.
2. Make sure the SQLite JDBC library is included in the project dependencies.
3. Make sure the database file is available in the expected project location.
4. Build the project.
5. Run the main class of the application.

The application will open the main hospital management window.

The application performs validation for several user operations.

* Empty required fields
* Invalid numeric input
* Invalid patient age
* Invalid ward capacity
* Duplicate ward names
* Full wards
* Invalid appointment times
* Doctor availability

## 12. Important Design Decisions

The project separates the main responsibilities of the application:

```text
GUI
 │
 ▼
HospitalSystem
 │
 ├── Patients
 ├── Doctors
 ├── Wards
 ├── Appointments
 ├── Medical Services
 └── Hospital Income
 │
 ▼
Database
```

The GUI is responsible for displaying information and receiving user input.

`HospitalSystem` contains the main business operations.

Database classes are responsible for persistence.

This separation makes the project easier to understand, maintain, and extend.
